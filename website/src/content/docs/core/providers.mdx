title: AI Providers
description: Connect to Claude, OpenAI, Gemini, or any OpenAI-compatible server with one config.
---

ChatCops puts every provider behind the same `AIProvider` interface. Switch between Claude, OpenAI, and Gemini by changing one config value.

## Provider configuration

```typescript
// Claude (Anthropic)
provider: {
  type: 'claude',
  apiKey: process.env.ANTHROPIC_API_KEY!,
  model: 'claude-haiku-5-5',  // Default
}

// OpenAI
provider: {
  type: 'openai',
  apiKey: process.env.OPENAI_API_KEY!,
  model: 'gpt-5-mini',  // Default
}

// Google Gemini
provider: {
  type: 'gemini',
  apiKey: process.env.GOOGLE_AI_API_KEY!,
  model: 'gemini-3.5-flash-lite',  // Default
}
```

## Default models

| Provider | Default model | SDK | Streaming |
|----------|---------------|-----|-----------|
| Claude | `claude-haiku-5-5` | `@anthropic-ai/sdk` | `messages.stream()` |
| OpenAI | `gpt-5-mini` | `openai` | `chat.completions.create({ stream: true })` |
| Gemini | `gemini-3.5-flash-lite` | `@google/genai` | `models.generateContentStream()` |

Set `model` to use any other model the provider offers.

## Options

| Option | Providers | Default | What it does |
|--------|-----------|---------|--------------|
| `model` | all | see above | The model id. |
| `effort` | all | `'low'` | How much effort the model spends per reply: `'low'`, `'medium'`, `'high'`, `'xhigh'` or `'max'`. Lower is faster and cheaper, which suits chat. Sent as `output_config.effort` to Claude 4.6 and later, `reasoning_effort` to OpenAI reasoning models, and `thinkingLevel` to Gemini 3 models. Models without an effort setting ignore it. |
| `baseURL` | all | provider default | A custom API endpoint: a proxy, a gateway, or an OpenAI-compatible server. |
| `fetch` | all | the global `fetch` | The `fetch` the provider SDK sends requests with. Use it to route requests through a proxy, or to replay recorded responses in tests. |
| `organization` | OpenAI | none | Your OpenAI organization id. |
| `maxTokensParam` | OpenAI | `'max_completion_tokens'` | Set to `'max_tokens'` for OpenAI-compatible servers that only accept the old parameter name. |

The server config's `maxTokens` (default 4096) and `temperature` are passed to the provider on every request.

### Temperature on newer models

Claude 5.x models, Claude Opus 4.7 and later, and OpenAI reasoning models (GPT-5 and later, o-series) don't accept a custom `temperature`. ChatCops leaves it out for those models and logs a one-time warning. Use `effort` instead.

## OpenAI-compatible servers

Any server that speaks the OpenAI chat completions API works through the `openai` provider with a `baseURL`:

```typescript
// Ollama on your own machine
provider: {
  type: 'openai',
  apiKey: 'ollama',  // Ollama ignores the key, but the SDK needs one
  model: 'llama3.3',
  baseURL: 'http://localhost:11434/v1',
}

// OpenRouter
provider: {
  type: 'openai',
  apiKey: process.env.OPENROUTER_API_KEY!,
  model: 'anthropic/claude-haiku-5-5',
  baseURL: 'https://openrouter.ai/api/v1',
}
```

If the server rejects `max_completion_tokens`, add `maxTokensParam: 'max_tokens'`.

## Conversation history

Before each request ChatCops cleans up the stored history so every provider accepts it. The history always starts with a user message, and two messages in a row from the same side are joined into one. This happens, for example, when a reply failed and the visitor sent their message again.

## AIProvider interface

```typescript
interface AIProvider {
  name: string;
  model?: string;
  // One model request: streams text, then reports tool calls, token usage
  // and why the model stopped. Runs no tools. Optional, so providers written
  // for 0.4 with only chat() keep working.
  step?(params: ProviderStepParams): AsyncGenerator<ProviderEvent>;
  chat(params: ProviderChatParams): AsyncGenerator<string>;
  chatSync(params: ProviderChatParams): Promise<string>;
}

interface ProviderChatParams {
  messages: ChatMessage[];
  systemPrompt: string;
  tools?: ToolDefinition[];
  maxTokens?: number;      // Default: 4096
  temperature?: number;    // Left out on models that don't accept it
}
```

## Direct provider usage

For advanced use cases, you can use providers directly:

```typescript
import { createProvider } from '@chatcops/core';

const provider = await createProvider({
  type: 'claude',
  apiKey: process.env.ANTHROPIC_API_KEY!,
});

// Streaming
for await (const token of provider.chat({
  messages: [{ id: '1', role: 'user', content: 'Hello!', timestamp: Date.now() }],
  systemPrompt: 'You are helpful.',
})) {
  process.stdout.write(token);
}

// Non-streaming
const response = await provider.chatSync({
  messages: [{ id: '1', role: 'user', content: 'Hello!', timestamp: Date.now() }],
  systemPrompt: 'You are helpful.',
});
console.log(response);
```

## Running a turn

`runTurn()` is what sits between a provider and the server: it calls `step()`, runs the tools the model asks for, and repeats until the model answers, up to 5 tool rounds. It yields the parts the widget receives (`text-delta`, `tool-call`, `lead-captured`, `finish` and so on) and returns the reply as a `ChatMessage`.

```typescript
import { createProvider, runTurn, toolRegistry } from '@chatcops/core';

const provider = await createProvider({ type: 'claude', apiKey: process.env.ANTHROPIC_API_KEY! });
const turn = runTurn({
  provider,
  messages: [{ id: '1', role: 'user', content: 'Where is order A-1001?', timestamp: Date.now() }],
  systemPrompt: 'You are helpful.',
  tools: toolRegistry([lookupOrderTool]),
  conversationId: 'c1',
});

for await (const part of turn) {
  if (part.type === 'text-delta') process.stdout.write(part.delta);
}
```

Provider errors don't throw. They end the turn with an `error` part and a `finish` part with reason `error`. `chat()` and `chatSync()` on the built-in providers are now thin wrappers over `runTurn()` that still throw as they did in 0.5.

For tests, `@chatcops/core/testing/provider` has `scriptedProvider()`, which plays back a script of steps instead of calling a model.

## Tool support

All providers support tool calling with one tool format. ChatCops converts tool definitions to each provider's native format:

- Claude: `tools` array with `input_schema`
- OpenAI: `tools` array with `function.parameters`
- Gemini: `functionDeclarations` with `parametersJsonSchema`

When the model calls several tools at once, they run in parallel on every provider.

```typescript
chatcopsMiddleware({
  provider: { type: 'claude', apiKey: '...' },
  systemPrompt: '...',
  tools: [new LeadCaptureTool(saveLead)],
});
```

The same tool definition works across all providers without changes.
