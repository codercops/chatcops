Knowledge sources give the AI relevant context for each query, grounding responses in your actual content.

## FAQ Knowledge Source

Best for structured question-answer pairs:

```typescript
import { FAQKnowledgeSource } from '@chatcops/core';

const faq = new FAQKnowledgeSource([
  { question: 'What are your business hours?', answer: '9am-5pm EST, Monday to Friday.' },
  { question: 'Do you offer refunds?', answer: 'Yes, full refunds within 30 days.' },
  { question: 'How do I contact support?', answer: 'Email support@example.com or use this chat!' },
  { question: 'What payment methods do you accept?', answer: 'Visa, Mastercard, PayPal, and wire transfer.' },
]);
```

### How FAQ Matching Works

1. User's query is tokenized into words
2. Each FAQ pair is scored by word frequency overlap (question + answer)
3. Top 5 matching FAQs are returned as context
4. Context is formatted as `Q: ...\nA: ...` and injected into the AI prompt

## Text Knowledge Source

Best for unstructured content (documentation, product descriptions, policies):

```typescript
import { TextKnowledgeSource } from '@chatcops/core';

const docs = new TextKnowledgeSource([
  `Our company was founded in 2020 by Jane Doe.
  We specialize in AI-powered customer support solutions.
  Our flagship product is ChatCops, an embeddable chatbot widget.
  We serve over 500 businesses worldwide.
  Our headquarters is in San Francisco, CA.`,
]);
```

### How Text Matching Works

1. Each string in the array is one chunk
2. User's query words are matched against each chunk
3. Top 3 relevant chunks are returned
4. Context is prefixed with `"Relevant context:\n"`

## KnowledgeSource Interface

```typescript
import type { RetrievalQuery, RetrievedChunk } from '@chatcops/core';

interface KnowledgeSource {
  type: string;
  getContext(query: string): Promise<string>;
  // Optional: the matching chunks themselves, with the conversation so far.
  retrieve?(query: RetrievalQuery): Promise<RetrievedChunk[]>;
}
```

When a source has `retrieve`, the server uses it instead of `getContext`. It passes the visitor's message and the last few messages before it, so a follow-up like "how long does it take?" can be searched in context. The chunks from every source are numbered and given to the model in one fenced block, marked as reference material that never contains instructions, since crawled pages sometimes do. That's what citations will build on.

## Multiple Sources

Combine multiple knowledge sources — all contexts are concatenated:

```typescript
import { FAQKnowledgeSource, TextKnowledgeSource } from '@chatcops/core';
import { chatcopsMiddleware } from '@chatcops/server';
import type { FAQPair } from '@chatcops/core';

const faqs: FAQPair[] = [{ question: 'What are your hours?', answer: '9am-5pm EST.' }];
const productDocs = 'Our product is ChatCops.';
const policyDocs = 'Refunds are available within 30 days.';

chatcopsMiddleware({
  provider: { type: 'claude', apiKey: '...' },
  systemPrompt: 'Answer using the provided context. If unsure, say so.',
  knowledge: [
    new FAQKnowledgeSource(faqs),
    new TextKnowledgeSource([productDocs]),
    new TextKnowledgeSource([policyDocs]),
  ],
});
```

## Custom Knowledge Source

Implement `KnowledgeSource` for database-backed or vector search:

```typescript
import type { KnowledgeSource } from '@chatcops/core';

const vectorDB = { async search(_query: string, _options: { topK: number }) { return [] as Array<{ text: string }>; } };

class VectorKnowledgeSource implements KnowledgeSource {
  type = 'vector';

  async getContext(query: string): Promise<string> {
    const results = await vectorDB.search(query, { topK: 5 });
    return results.map(r => r.text).join('\n\n');
  }
}
```

## Retrieval from a vector store

Embedders turn text into vectors. `openaiEmbedder` calls OpenAI's embeddings API (`text-embedding-3-small` at 1024 dimensions by default), while `workersAiEmbedder` runs inside Cloudflare Workers using the native `env.AI` binding (`@cf/baai/bge-m3` at 1024 dimensions by default, batched up to 100 texts). A retriever searches a vector store with them, and `retrieverKnowledge` turns the retriever into a knowledge source:

```typescript
import { hybridRetriever, memoryVectors, openaiEmbedder, retrieverKnowledge } from '@chatcops/core';
import { chatcopsMiddleware } from '@chatcops/server';

const embedder = openaiEmbedder({ apiKey: process.env.OPENAI_API_KEY! });
const vectors = memoryVectors({ dimensions: embedder.dimensions });

const handler = chatcopsMiddleware({
  provider: { type: 'claude', apiKey: process.env.ANTHROPIC_API_KEY! },
  systemPrompt: 'Answer questions about Acme.',
  knowledge: [retrieverKnowledge(hybridRetriever({ store: vectors, embedder }), { topK: 5 })],
});
```

`geminiEmbedder` does the same with [Google's Gemini API](https://ai.google.dev/gemini-api/docs/embeddings). It defaults to `gemini-embedding-001` at 1024 dimensions:

```typescript
import { geminiEmbedder } from '@chatcops/core';

const embedder = geminiEmbedder({ apiKey: process.env.GEMINI_API_KEY! });
```

`voyageEmbedder` does the same with [Voyage AI](https://docs.voyageai.com/reference/embeddings-api). It uses `voyage-4-large` at 1024 dimensions by default, and tells Voyage whether it is embedding a document or a search query, which Voyage embeds differently:

```typescript
import { voyageEmbedder } from '@chatcops/core';

const embedder = voyageEmbedder({ apiKey: process.env.VOYAGE_API_KEY! });
```

The newer Voyage models (`voyage-4`, `voyage-4-lite`, `voyage-3.5` and others) can shorten their vectors with `dimensions` (256, 512, 1024 or 2048). Other models make one fixed length, so set `dimensions` to that length. `batchSize` is how many texts go in one request (128 by default, at most 1,000); each model also limits the tokens in a request, so lower it for very long texts.

In a Cloudflare Worker, pass the `AI` binding directly:

```typescript
import {
  memoryVectors,
  retrieverKnowledge,
  vectorRetriever,
  workersAiEmbedder,
  type WorkersAiBinding,
} from '@chatcops/core';

declare const env: { AI: WorkersAiBinding };

const embedder = workersAiEmbedder({ ai: env.AI });
const vectors = memoryVectors({ dimensions: embedder.dimensions });
const knowledge = retrieverKnowledge(vectorRetriever({ store: vectors, embedder }), { topK: 5 });
```

There are two retrievers:

| Retriever | Searches by | Needs |
|---|---|---|
| `vectorRetriever({ store, embedder })` | Meaning: the question is embedded and compared with every chunk | Any vector store |
| `hybridRetriever({ store, embedder })` | Meaning and exact words, merged by rank (reciprocal rank fusion, `rrfK` 60) | A store with `keywordQuery` |

Hybrid search is the better default when the store supports it. Words catch what meaning misses, such as product names, error codes and part numbers.

Both take `candidates` (how many records each search fetches, default 20) and an optional `reranker`, which reorders the candidates before the top ones are kept. A short follow-up question ("how long does it take?") is searched together with the visitor's previous question, so it finds the right pages.

The index has to be built and searched with the same embedder; a retriever refuses an embedder whose vectors are a different size from the store's. A command that builds the index from your sitemap is next.
