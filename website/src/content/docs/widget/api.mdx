The `ChatCops` singleton is exposed on `window.ChatCops` by the script tag build (`chatcops.min.js` or `chatcops.full.min.js`), or importable from the ESM bundle.

## Methods

### `ChatCops.init(config)`

Initialize the widget with a configuration object. Must be called before any other method if not using script tag auto-init.

```typescript
// Popup mode (default)
ChatCops.init({
  apiUrl: 'https://your-api.com/chat',
  theme: { accent: '#6366f1' },
  branding: { name: 'My Bot' },
  welcomeMessage: 'Hello! How can I help?',
});

// Inline mode
ChatCops.init({
  apiUrl: 'https://your-api.com/chat',
  mode: 'inline',
  container: '#chat-container',
  branding: { name: 'My Bot' },
});
```

Calling `init()` again will destroy the previous instance and create a new one.

In the ESM and single-file builds, `init()` returns the `Widget` instance. In the script tag loader (`chatcops.min.js`) it returns nothing, since the chat itself loads later. Use the `ChatCops` methods there, which work before and after the chat has loaded.

### `ChatCops.open()`

Programmatically open the chat panel.

- **Popup mode:** Shows the panel and updates the FAB icon.
- **Inline mode:** Shows the panel (useful if you've previously called `close()`).

```typescript
document.querySelector('#help-btn')?.addEventListener('click', () => {
  ChatCops.open();
});
```

### `ChatCops.close()`

Close the chat panel.

- **Popup mode:** Hides the panel and resets the FAB icon.
- **Inline mode:** Hides the panel. Call `open()` to show it again.

```typescript
ChatCops.close();
```

### `ChatCops.toggle()`

Open the chat if it's closed, and close it if it's open. With the script tag build, the first call loads the chat.

```typescript
document.querySelector('#help-btn')?.addEventListener('click', () => ChatCops.toggle());
```

### `ChatCops.sendMessage(text, options?)`

Send a message as if the visitor typed it, for example from a "Ask about pricing" button on your page. The chat opens first, unless you pass `{ open: false }`. The promise resolves when the reply has finished. While a reply is still coming, another message is ignored, as it is in the input.

```typescript
document.querySelector('#pricing-question')?.addEventListener('click', () => {
  void ChatCops.sendMessage('How much is the Team plan?');
});
```

### `ChatCops.newConversation()`

Start a fresh conversation: a new conversation id, and the chat back to the welcome message. A reply that's still coming is stopped. Pre-chat answers are kept, so the visitor isn't asked again.

```typescript
ChatCops.newConversation();
```

### `ChatCops.clear()`

Like `newConversation()`, and also removes what the widget saved in this browser: the transcript and the pre-chat answers, so the form shows again. Use it when a visitor signs out.

```typescript
ChatCops.clear();
```

### `ChatCops.destroy()`

Completely remove the widget from the DOM and clean up all event listeners.

- **Popup mode:** Removes FAB, panel, and welcome bubble from the page.
- **Inline mode:** Removes the widget from the container element.

```typescript
ChatCops.destroy();
```

### `ChatCops.on(event, callback)`

Subscribe to widget events. Returns an unsubscribe function.

Handlers can be registered before `init()` (including from inline scripts before `DOMContentLoaded`), and are preserved across repeated `init()` calls.

```typescript
const unsub = ChatCops.on('message', (data) => {
  console.log('New message:', data);
});

// Later, remove the listener:
unsub();
```

### `ChatCops.off(event, callback)`

Remove a specific event listener from both the persistent registry and the active widget instance.

```typescript
function onOpen() {
  console.log('Widget opened');
}

ChatCops.on('open', onOpen);
ChatCops.off('open', onOpen);
```

### `ChatCops.setUser(user)`

Tell the widget who the signed-in visitor is.

- `token` is the identity token for [signed-in visitors](/server/setup/#signed-in-visitors), which your server signs.
- `name` and `email` are sent to the bot as visitor details with the first message of a conversation, and the name greets them.

Switching to another user, or `setUser(null)` when the visitor signs out, clears the chat, so one person's conversation never shows for the next. With the script tag build, a call before the chat has loaded is kept until it does.

```typescript
declare const session: { name: string; email: string; chatToken: string };

ChatCops.setUser({ name: session.name, email: session.email, token: session.chatToken });

// When the visitor signs out:
ChatCops.setUser(null);
```

### `ChatCops.setContext(data)`

Details the bot should know for the next messages, such as the visitor's plan or what's in their cart. They're sent with each message as page context: at most 20 fields, keys up to 40 characters, values up to 500. The bot sees them as details the page added, not as verified facts. `setContext(null)` removes them. Nothing is sent when `pageContext: false`.

```typescript
ChatCops.setContext({ plan: 'Team', seats: '12' });
```

### `ChatCops.registerLocale(code, strings, options?)`

Add a language the widget doesn't ship, or replace one of its own. Strings you leave out stay in English. Pass `{ dir: 'rtl' }` for a right-to-left language. Register before `init()`, then use the code as `locale`.

```typescript
ChatCops.registerLocale('sv', {
  welcomeMessage: 'Hur kan jag hjälpa dig?',
  inputPlaceholder: 'Skriv ett meddelande…',
  sendButton: 'Skicka',
});
ChatCops.init({ apiUrl: '/api/chat', locale: 'sv' });
```

See [Internationalization](/widget/i18n/) for every string.

### `ChatCops.version`

The widget's version, such as `"0.7.0"`.

## Auto-Initialization

When using the CDN script tag, the widget auto-initializes by reading `data-*` attributes:

### Popup (default)

```html
<script
  src="https://cdn.jsdelivr.net/npm/@chatcops/widget/dist/chatcops.min.js"
  data-api-url="https://your-api.com/chat"
  data-accent="#6366f1"
></script>
```

### Inline

```html
<div id="my-chat" style="width: 400px; height: 500px;"></div>
<script
  src="https://cdn.jsdelivr.net/npm/@chatcops/widget/dist/chatcops.min.js"
  data-api-url="https://your-api.com/chat"
  data-mode="inline"
  data-container="#my-chat"
></script>
```

The script tag approach is equivalent to calling `ChatCops.init()` with the corresponding config. You can still use the programmatic API after auto-init (e.g., `ChatCops.open()`).

## ESM Usage

```typescript
import ChatCops from '@chatcops/widget';

// Popup
ChatCops.init({ apiUrl: '/api/chat' });

// Inline with element reference
const el = document.getElementById('chat');
if (!el) throw new Error('Chat container not found');
ChatCops.init({
  apiUrl: '/api/chat',
  mode: 'inline',
  container: el,
});

// Use methods as needed
ChatCops.on('message', (msg) => console.log(msg));
```

## React / Framework Usage

For inline mode in React or other frameworks, pass the container element directly:

```tsx
import { useEffect, useRef } from 'react';
import ChatCops from '@chatcops/widget';

function Chat() {
  const ref = useRef(null);

  useEffect(() => {
    if (!ref.current) return;
    ChatCops.init({
      apiUrl: '/api/chat',
      mode: 'inline',
      container: ref.current,
    });
    return () => ChatCops.destroy();
  }, []);

  return <div ref={ref} style={{ width: 400, height: 500 }} />;
}
```
