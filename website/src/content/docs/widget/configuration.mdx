The widget can be configured via `data-*` attributes on the script tag or programmatically via `ChatCops.init()`.

## Content Security Policy

If your site's Content Security Policy requires a nonce for inline styles, add the same per-response nonce to the widget script tag. Script-tag installs, including `chatcops.full.min.js`, read their script element's `nonce` and apply it to the launcher, chat panel, and lazy pre-chat form styles. For ESM and other programmatic `ChatCops.init()` calls, pass it as `nonce`:

```typescript
ChatCops.init({ apiUrl: '/api/chat', nonce: 'YOUR_RESPONSE_NONCE' });
```

Include that nonce in your response's `style-src` policy. Generate a fresh, unpredictable nonce for each response and use it for both the policy and widget script.

## Display Modes

ChatCops supports two display modes:

- **Popup** (default) — Floating action button (FAB) in the corner that opens a chat panel overlay.
- **Inline** — The chat panel renders directly inside a container element on your page. No FAB, no overlay.

## Script Tag Attributes

### Popup Mode (default)

```html
<script
  src="https://cdn.jsdelivr.net/npm/@chatcops/widget/dist/chatcops.min.js"
  nonce="YOUR_RESPONSE_NONCE"
  data-api-url="https://your-api.com/chat"
  data-accent="#6366f1"
  data-text-color="#FAFAF9"
  data-bg-color="#0A0A0A"
  data-font-family="Inter, sans-serif"
  data-border-radius="12"
  data-position="bottom-right"
  data-brand-name="Support Bot"
  data-brand-avatar="https://example.com/avatar.png"
  data-brand-subtitle="Usually replies instantly"
  data-welcome-message="Hi! How can I help you today?"
  data-welcome-bubble="Need help? Chat with us!"
  data-welcome-bubble-delay="3000"
  data-placeholder="Type a message..."
  data-locale="en"
  data-auto-open="1000"
></script>
```

### Inline Mode

```html
<div id="chat-container" style="width: 400px; height: 500px;"></div>
<script
  src="https://cdn.jsdelivr.net/npm/@chatcops/widget/dist/chatcops.min.js"
  data-api-url="https://your-api.com/chat"
  data-mode="inline"
  data-container="#chat-container"
  data-brand-name="Support Bot"
  data-welcome-message="Hi! How can I help you today?"
></script>
```

In inline mode, the chat panel fills the container element. You control the size via the container's CSS.

## Programmatic Configuration

### Popup Mode

```typescript
import ChatCops from '@chatcops/widget';

ChatCops.init({
  apiUrl: 'https://your-api.com/chat',
  timeout: 60000, // Abort after 60s without received data (default: 30000ms)

  // Theme
  theme: {
    mode: 'auto',               // 'light' | 'dark' | 'auto' (follows the system)
    accent: '#4f46e5',
    accentDark: '#a5b4fc',      // optional accent for dark mode
    fontFamily: 'Inter, sans-serif',
    borderRadius: '12',
    position: 'bottom-right',   // 'bottom-right' | 'bottom-left'
  },

  // Branding
  branding: {
    name: 'Support Bot',
    avatar: 'https://example.com/avatar.png',
    subtitle: 'Usually replies instantly',
  },

  // Behavior
  welcomeMessage: 'Hi! How can I help you today?',
  suggestions: ['Compare plans', 'Book a demo'],
  welcomeBubble: {
    text: 'Need help? Chat with us!',
    delay: 3000,
  },
  placeholder: 'Type a message...',
  autoOpen: 1000,  // Open after 1s, or true for immediate
  locale: 'en',
});
```

### Inline Mode

```typescript
import ChatCops from '@chatcops/widget';

ChatCops.init({
  apiUrl: 'https://your-api.com/chat',
  mode: 'inline',
  container: '#chat-container',  // CSS selector or HTMLElement

  branding: {
    name: 'Support Bot',
    subtitle: 'Online',
  },
  welcomeMessage: 'Hi! How can I help you today?',
  persistence: 'none',
});
```

The `container` option accepts a CSS selector string or a direct `HTMLElement` reference.

### More than one widget on a page

Each widget saves its conversation in the browser. A page with one widget needs nothing extra. When a page has two, for example a popup and an inline demo, give each a `siteId` so they keep separate conversations:

```typescript
import ChatCops, { Widget } from '@chatcops/widget';

ChatCops.init({ apiUrl: '/api/chat', siteId: 'support' });

new Widget({
  apiUrl: '/api/chat',
  mode: 'inline',
  container: '#demo',
  siteId: 'demo',
}).init();
```

If you leave `siteId` out, the first widget keeps the default storage and the next one is given its own, with a note in the console. The first widget's host element has the id `chatcops-root`; later ones get `chatcops-root-2` and so on, and every host has the class `chatcops-root`.

### Saved conversations

The widget keeps the conversation so a visitor who reloads the page or comes back later picks up where they left off. `persistence` picks where:

| Value | Kept in | Lasts |
|-------|---------|-------|
| `'local'` (default) | `localStorage` | Until `historyTtlDays` passes, 30 days by default |
| `'session'` | `sessionStorage` | Until the tab is closed |
| `'none'` | Memory | Until the page reloads |

```typescript
ChatCops.init({
  apiUrl: '/api/chat',
  persistence: 'session',
});

// Or keep it in the browser, for a week
ChatCops.init({
  apiUrl: '/api/chat',
  historyTtlDays: 7,
});
```

A popup doesn't read or write storage until the visitor opens it. Until then, nothing is stored on the visitor's device. An inline chat is on screen from the start, so it reads its saved conversation when it mounts. The one exception is a welcome bubble with `showOnce`. It checks and sets its own flag when it's due to appear, and stores nothing before that. With `persistence: 'none'` nothing at all is written to storage, the bubble flag included.

The pre-chat form's answers are saved with the conversation, so they expire with it too.

`persistHistory` was removed in 1.0. A config that still sets it throws, so a site that asked for nothing to be saved never starts saving conversations. Use `persistence: 'none'` instead.

### Waiting for cookie consent

A site under a strict consent policy can hold the chat back until the visitor accepts functional cookies. Set `waitForConsent` (or `data-wait-for-consent` on the script tag) and the launcher shows as usual, but opening the chat shows a notice instead of the conversation: "Chat is available once you accept functional cookies." While it waits, the widget reads and writes no `localStorage` or `sessionStorage`, not even to check, and it makes no request to your chat server. The welcome bubble stays hidden too, since it remembers that it was shown.

```typescript
declare const consentBanner: { open(): void };

ChatCops.init({
  apiUrl: '/api/chat',
  waitForConsent: true,
  // The notice's button. Open your own consent banner here. Without it, the notice has no button.
  onConsentRequest: () => consentBanner.open(),
});

// When the visitor accepts functional cookies:
ChatCops.setConsent(true);

// If they withdraw it later:
ChatCops.setConsent(false);
```

`setConsent(true)` replaces the notice with the normal chat: the saved conversation comes back and the session starts. A chat the visitor has closed stays closed. It works before or after `init()`, and with the script tag build also before the chat has loaded. `setConsent(false)` closes the chat and removes what the widget saved in this browser (the conversation, the session token and the welcome bubble's flag), and the notice shows again on the next open. If the visitor never gave consent in this page view, `setConsent(false)` does nothing and touches no storage. While consent is missing, `sendMessage()` resolves without sending, so don't wait on a reply.

The notice's wording is `consentNotice` and `consentButton` in the [locale](/widget/i18n/), and a language that doesn't have them yet shows them in English.

### AI disclosure

A new conversation starts with a short note: "You're chatting with an AI assistant. It can make mistakes." The EU AI Act (Article 50) asks that people know when they're talking to an AI, and the note stays at the top of the chat, also after "New conversation". Its strings are `disclosure` and `disclosureLearnMore` in the locale, and a language that doesn't have them yet shows them in English.

Change the wording, or add a link to a page that explains more:

```typescript
ChatCops.init({
  apiUrl: '/api/chat',
  disclosure: {
    text: 'Acme Assistant is an AI. It can get things wrong, so check anything important.',
    learnMoreUrl: 'https://acme.com/ai',
  },
});
```

`disclosure: false` (or `data-disclosure="false"`) removes it. The widget then logs a note in the console, because telling visitors some other way is up to you.

### Streaming inactivity timeout

Set `timeout` in `ChatCops.init()` to change the inactivity timeout in milliseconds.
The default is `30000` (30 seconds). It starts when a request begins and restarts
whenever a nonempty stream chunk arrives, including heartbeat comments, partial
SSE events and malformed data. It measures received transport activity, not the
time between displayed text updates or the total response duration.

A response can stream for longer than the timeout as long as chunks keep arriving.
A request that never responds, or a stream that stops sending data, fails with a
timeout error. Use a larger value for backends with longer silent periods. This
option is available through programmatic configuration.

## WidgetConfig Interface

`WidgetConfig` and the types it's made of are all exported from `@chatcops/widget`, so a site can type its own pieces of a config:

```typescript
import type { PreChatFormConfig, ThemeConfig } from '@chatcops/widget';

const brand: ThemeConfig = { mode: 'auto', accent: '#2563eb', borderRadius: 12 };
const leadForm: PreChatFormConfig = {
  enabled: true,
  fields: [{ name: 'email', label: 'Work email', type: 'email', required: true }],
};
```

```typescript
// docs-check: skip, a reference listing rather than code to run
interface WidgetConfig {
  apiUrl: string;
  nonce?: string;                // CSP nonce for the widget's injected styles
  timeout?: number;              // Inactivity timeout in ms, default: 30000
  turnstileSiteKey?: string;     // Cloudflare Turnstile site key, when the server has `turnstile` set
  userToken?: string | (() => string | undefined | Promise<string | undefined>); // Your server's signed token for a signed-in visitor (server `identity`), or a function that returns a fresh one

  // Display mode
  mode?: 'popup' | 'inline';       // Default: 'popup'
  container?: string | HTMLElement; // Required when mode is 'inline'
  siteId?: string;                 // Names the saved conversation; set one per widget when a page has several

  theme?: {
    mode?: 'light' | 'dark' | 'auto';  // Default: 'auto', which follows the system setting
    accent?: string;          // Hex color, default: '#4f46e5' (light), '#6366f1' (dark)
    accentDark?: string;      // Hex color, the accent in dark mode. Default: accent
    textColor?: string;       // Hex color, replaces the text color in every mode
    bgColor?: string;         // Hex color, replaces the background in every mode
    fontFamily?: string;      // CSS font-family
    borderRadius?: string | number;  // px if a number or numeric string (12, '12'), or any CSS length ('1rem'). Default: 12
    position?: 'bottom-right' | 'bottom-left';
  };

  branding?: {
    name?: string;            // Header title
    avatar?: string;          // URL or data URI
    subtitle?: string;        // Below title in header
  };

  welcomeMessage?: string;    // First assistant message
  disclosure?: false | {      // The "you're chatting with an AI" note, on by default
    text?: string;            // Replaces the wording
    learnMoreUrl?: string;    // Adds a "Learn more" link (http or https)
  };
  suggestions?: string[];     // Suggested question buttons shown in a new conversation
  welcomeBubble?: {           // Popup mode only
    text: string;             // Text shown on hover bubble
    delay?: number;           // ms before bubble appears
    showOnce?: boolean;       // Only show once per session
  };
  placeholder?: string;       // Input placeholder text
  persistence?: 'local' | 'session' | 'none'; // Where the chat is saved, default: 'local'
  historyTtlDays?: number;    // Drop saved chats older than this, default: 30
  waitForConsent?: boolean;   // Show a notice and use no storage or API until setConsent(true), default: false
  onConsentRequest?: () => void; // The notice's button; leave it out to have no button
  maxMessages?: number;       // Max messages to persist, default: 50
  pageContext?: boolean;       // Send page URL/title, default: true
  autoOpen?: boolean | number; // Popup mode only. true = immediate, number = delay in ms
  locale?: string;            // Sent to the server with each message. Only English strings are built in
  dir?: 'ltr' | 'rtl' | 'auto'; // Text direction; defaults from locale, then document direction
  strings?: Partial<WidgetLocaleStrings>; // Custom i18n overrides
  preChatForm?: {
    enabled: boolean;
    title?: string;
    subtitle?: string;
    submitLabel?: string;
    fields: Array<{
      name: string;
      type: 'text' | 'email' | 'select' | 'textarea';
      label: string;
      placeholder?: string;
      required?: boolean;
      options?: string[];
    }>;
  };

  // Callbacks
  onOpen?: () => void;
  onClose?: () => void;
  onMessage?: (message: MessageData) => void;
  onError?: (error: Error) => void;
  onLeadCaptured?: (leadData?: Record<string, unknown>) => void;
  onPreChatSubmit?: (data: Record<string, string>) => void;
}
```

See the [pre-chat form guide](/widget/pre-chat-form) for field behavior, validation, and how answers are sent to the server. The form is configured with JavaScript; it has no `data-*` attributes.

## Inline Mode Behavior

When using `mode: 'inline'`:

- The chat panel renders inside the specified container element
- No floating action button (FAB) is created
- No welcome bubble is shown
- The panel is visible immediately (no toggle needed)
- `autoOpen` is ignored (always open)
- The panel fills 100% width and height of the container
- Mobile responsive overrides do not apply — the container controls sizing
- `open()` and `close()` still work programmatically
