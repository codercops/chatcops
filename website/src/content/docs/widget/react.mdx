The `@chatcops/react` package provides a `<ChatCops>` component and `useChatCops()` hook for React and Next.js applications. It manages widget initialization, prop updates, event subscriptions, cleanup on unmount, and React StrictMode development safely without touching `window` on the server.

## Installation

Install `@chatcops/react` along with `@chatcops/widget`:

```bash
npm install @chatcops/react @chatcops/widget
```

## Quick Start

In Next.js (App Router) or any React app, place `<ChatCops>` in your root layout:

```tsx
'use client';

import { ChatCops, useChatCops } from '@chatcops/react';

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="en">
      <body>
        {children}
        <ChatCops
          apiUrl="/api/chat"
          branding={{ name: 'Acme' }}
          onLeadCaptured={(lead) => console.log('Lead captured:', lead)}
        />
      </body>
    </html>
  );
}
```

Trigger actions anywhere in your application using `useChatCops()`:

```tsx
'use client';

import { useChatCops } from '@chatcops/react';

export function AskProductButton({ productName }: { productName: string }) {
  const chat = useChatCops();

  return (
    <button onClick={() => chat.send(`Is ${productName} in stock?`)}>
      Ask about this product
    </button>
  );
}
```

## `<ChatCops>` Component

`<ChatCops>` renders nothing (`null`) to the DOM. It loads `@chatcops/widget` dynamically in an effect on the client, making it safe for Server-Side Rendering (SSR).

> **Important**: Render only one `<ChatCops>` component per page. A second instance replaces the first, matching `ChatCops.init()` behavior.

### Props

`<ChatCops>` accepts all options from `WidgetConfig` (such as `apiUrl`, `branding`, `theme`, `mode`, `container`, `welcomeMessage`, `placeholder`, `suggestions`, `disclosure`, `privacyUrl`, `waitForConsent`), plus callback event props:

| Prop | Type | Description |
| :--- | :--- | :--- |
| `apiUrl` | `string` | URL of your ChatCops server endpoint (required). |
| `branding` | `{ name?, avatar?, subtitle? }` | Bot name, avatar URL, and subtitle. |
| `theme` | `ThemeConfig` | Accent colors, position (`bottom-right`, `bottom-left`), font family, border radius. |
| `onOpen` | `() => void` | Fires when the chat window opens. |
| `onClose` | `() => void` | Fires when the chat window closes. |
| `onMessage` | `(message: MessageData) => void` | Fires on visitor messages and assistant replies. |
| `onError` | `(error: Error) => void` | Fires when an error occurs during chat. |
| `onLeadCaptured` | `(lead?: Record<string, unknown>) => void` | Fires when a visitor submits lead details. |
| `onPreChatSubmit` | `(data: Record<string, string>) => void` | Fires when the pre-chat form is submitted. |

### Prop Updates

When props change:

- Props supported by `update()` (`branding`, `welcomeMessage`, `suggestions`, `placeholder`, `strings`, `theme` color tokens, `privacyUrl`, `disclosure`) are applied smoothly via `ChatCops.update()`.
- Changing structural props such as `apiUrl`, `mode`, `container`, or `theme.position` destroys the previous widget and re-initializes cleanly.
- Event handlers are kept in refs: changing an inline arrow function prop on re-render never resubscribes listeners or recreates the widget.

## `useChatCops()` Hook

`useChatCops()` returns an object with helper methods to control the widget:

```tsx
const chat = useChatCops();
```

| Method | Type | Description |
| :--- | :--- | :--- |
| `chat.open()` | `() => void` | Opens the chat panel. |
| `chat.close()` | `() => void` | Closes the chat panel. |
| `chat.toggle()` | `() => void` | Toggles the chat panel open or closed. |
| `chat.send(text, options?)` | `(text: string, options?: { open?: boolean }) => Promise<void>` | Sends a message as the visitor. Opens the chat by default unless `open: false` is passed. Resolves when the assistant reply finishes streaming. |
| `chat.update(changes)` | `(changes: WidgetUpdate) => void` | Updates theme, branding, or strings on the active chat. |

Before the widget bundle has loaded on the client, these methods safely do nothing (`send()` returns a resolved promise).
